Development preview built on EAS, with the native AirPods Bluetooth module included.

## Install and connect

1. Install `pods-0.2.0-preview.1.apk` on your Android phone.
2. Run `npm run start:dev` from the project on your computer. Scan the new development QR code to open the project in **Pods**.
3. Pair your AirPods in Android Bluetooth settings, then choose them in Pods and allow Nearby devices access.

The APK uses the same signing certificate as the previous preview.

This is a development build. It loads the interface from a running Metro server, so it supports live interface updates while you test the native connection. Expo Go is not required.

## Changes

- Dedicated connection screen, with all sample readings, simulated switches, bottom tabs, and developer-explanation dialogs removed.
- A paired-device picker that includes renamed AirPods.
- Native battery notifications, listening-mode commands, conversation-awareness settings, ear status, and hardware model identification.
- Controls appear when the device reports their current state. Setting changes wait for a fresh device report, and unavailable batteries remain unknown.
- Material You wallpaper colors, rounded buttons, and system, light, or dark appearance settings behind the top-right button.

The model directory covers ordinary AirPods, Pro, and Max generations. Each model exposes different settings; inclusion in the directory does not establish physical-device compatibility.

## Validation

EAS completed the Android development build. Native Kotlin compilation, seven protocol tests, lint, and TypeScript checks passed. APK signature verification passed, and the native AirPods classes and ARM64 libraries are present in the APK.

The APK installed on the Android 17 emulator. Interactive runtime checks were blocked by an Android System UI ANR, which also prevented dismissing the system dialog. Navigation, theme switching, and the connection flow have not been verified interactively in this build.

## Compatibility

Android compatibility depends on the phone's Bluetooth stack. Recent Pixel Android 16 QPR3 or Android 17 builds with current Google Play system updates are the starting point. This preview uses a hidden classic Bluetooth API, so older or vendor-modified versions may reject the connection.

Physical Pixel 9 and AirPods compatibility has not been verified. Background reconnection, automatic playback pausing, conversation volume ducking, gesture customization, widgets, head tracking, and Apple account services remain future work. This preview does not provide full iPhone feature parity.
